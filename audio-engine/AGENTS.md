# Audio engine

- Use the custom vanilla HTML/CSS/JavaScript web app in `web/`; do not replace it with Gradio. The interface must have only one record/stop button: stopping automatically generates and loops the composition. Tapping again stops playback and records a new melody. No separate settings, upload, generate, download, or playback controls. Exception: `/?tune` mounts a developer tuning panel (built by `web/app.js`, never in `index.html`) to edit `engine.Options`, regenerate from the last hum or a file in `audio/` (listed by `GET /api/samples`, served at `/samples/`, decoded in the browser), and save defaults to `settings.json` via `GET`/`POST /api/settings`. `/api/compose` merges request settings over those saved defaults, so the one-button studio uses them.
- Run commands from `audio-engine/`. Install dependencies with `uv sync --locked`.
- Prepare pinned Stable Audio 3 Medium MLX weights with `uv run --locked python prepare.py`. If Hugging Face Xet stalls, use `HF_HUB_DISABLE_XET=1 uv run --locked python prepare.py`.
- Start the loopback-only API and GUI with `uv run --locked python app.py`; open `http://127.0.0.1:7860` directly. Proxy previews redirect to the canonical loopback origin so generation requests pass same-origin checks. The GUI can start setup via `POST /api/setup` and polls actual download progress until generation is ready.
- Fast tests: `uv run --locked python -m unittest -v` and `node --test test.mjs`. Syntax: `node --check web/app.js` and `uv run --locked python -m py_compile app.py engine.py prepare.py`.
- Browser smoke test (the server must be running): install the optional test browser with `uv run --with playwright==1.55.0 python -m playwright install chromium`, then run `uv run --with playwright==1.55.0 python browser_smoke.py`. It uses a fake microphone device and mocked model responses. Set `AUDIO_ENGINE_MODEL_TEST=1` on the browser test command to exercise real MLX inference and automatic loop playback with the default 15-second composition.
- Capture prefers MediaRecorder and converts browser audio to mono WAV; AudioWorklet is a bounded-time fallback. Never let a hanging recorder loader disable the entire studio indefinitely. Keep the AudioContext unlocked across recording and generation so the result starts automatically; use a looping AudioBufferSourceNode and stop it before re-recording.
- Real model integration test, after setup on Apple Silicon: `AUDIO_ENGINE_MODEL_TEST=1 uv run --locked python -m unittest -v test_engine.ModelIntegrationTests`. It checks that changing the reference audio changes the generated output; it does not measure musical quality or melody fidelity.
- `POST /api/compose` accepts multipart fields `audio` (WAV) and `settings` (JSON matching `engine.Options`), returning stereo PCM WAV and `X-Generation-Seed`. `GET /api/status` reports model readiness without downloading weights.
- The requested bundle is INT8 on disk; the official runtime uses dequantized FP16 DiT weights and FP32 SAME-L codecs. Downloads use about 5.53 GB, plus about 7 GB for converted runtime weights.
- The team frontend (`../frontend`, React) records a hum, posts it to `/api/compose` with `settings` `{}` through its Vite `/engine` proxy, and loops the result; it also polls `/api/status`. Keep both routes backward compatible. The proxy rewrites `Origin` only for the frontend's own requests, so keep the cross-origin POST check. `../start.sh` launches this server on port 7860.
- Keep model caches, virtual environments, recordings, and generated WAVs out of git. Never modify sibling demo folders when working on this engine. Audio-to-audio does not guarantee exact melody preservation.
